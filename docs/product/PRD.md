# Gauge · 量化人生 — 产品需求文档（PRD）

**版本**：MVP v0.1  
**仓库**：[WXKFelix/Gauge](https://github.com/WXKFelix/Gauge)（与 cloudWardrobe 完全独立）  
**一句话**：看清你走的线，算清岔口的代价。  
**英文**：Life, measured. Choices, clear.

---

## 1. 背景与问题

### 1.1 产品起源（P1）

人生像从锚点 **A** 出发的轨迹：前 20 年多在 A 附近；之后可能到 B、C、D，也可能终其一生仍在 A。离开时不一定「离 A 更远」。

**核心问题**：

- 人生**可以**被部分量化，但不应被压缩成单一 KPI。
- 用户需要：**更清晰的自我认知** + **关键岔口的可比较选项**，而不是排行榜或「人生总分」。

### 1.2 我们要解决什么

| 痛点 | 现状 | Gauge 的做法 |
|------|------|----------------|
| 日常失焦 | 忙但不知道是否贴近自己认定的主线 | 30 秒签到 + 对齐度 + 7 日趋势 |
| 大决策焦虑 | 换工作/Offer 信息杂、难权衡 | 规则引擎输出 2～3 条 Pareto 路径 + trade-off |
| 量化异化 | 指标绑架价值观（古德哈特定律） | 原则：数据是仆人；不可量化项必填；无人生总分 |

---

## 2. 产品原则与对外话术（P2）

### 2.1 三种视角 → 一条产品立场

1. **自我管理**：时间、健康、财务、成长、社交、情绪等**可测量**，但指标必须可关闭、可复盘，警惕「指标变成目标本身」。
2. **哲学批判**：爱、意义、美、自由、尊严**不能完全量化**；产品必须为叙述与底线留白。
3. **中间路线（Gauge 默认）**：数据服务价值观；定期问「这些数字还在帮我说真话吗？」；保留**无数据留白**。

### 2.2 对外话术（可直接用于 App / 官网）

- 「Gauge 不给你人生打分，只帮你看清此刻的线，和岔口的代价。」
- 「锚点 A 不是起点竞赛：半径小不等于空白人生。」
- 「关键节点给你 2～3 条较优路径，每条都有假设与复盘日——没有唯一标准答案。」
- 「可以关掉任何指标；三条『最不想失去』和叙述，永远比分数重要。」

### 2.3 明确禁止（产品红线）

- 人生总分、全球/好友排行榜、单线「你应该……」
- 焦虑式 KPI 动画、离 A 越远越成功的视觉隐喻
- LLM **编造**薪资、通勤等数值（若接入 LLM，仅解释与追问）

## 3. 核心模型：A → B → C 轨迹（P3）

### 3.1 隐喻

- **锚点 A**：出身/长期根基（地理或心理），方差小 ≠ 失败。
- **阶段 / 站点**：B、C、D… 人生章节，可增删改。
- **叙事**：不可完全量化的故事与意义，**必填能力**（至少关键决策时）。
- **状态快照**：某一时刻可量化的侧写（精力、投入、情绪等）。

### 3.2 数据概念（逻辑模型）

| 实体 | 说明 |
|------|------|
| `profile` | 价值观权重、人生主线、锚点 A、当前站 |
| `life_stages` | 阶段 id、标题、起止、叙述、排序 |
| `daily_checkins` | 日期、精力、主线投入、情绪、可选笔记 |
| `decisions` | 类型（MVP：`job_offer`）、输入、输出路径、假设、复盘日 |
| `value_snapshot` | 只读衍生：对齐度、趋势，**非**排名 |

### 3.3 UI 原则

- **垂直时间线**展示轨迹，禁止「离 A 越远越成功」的单一路线偏见。
- 锚点 A 用 accent 色强调「根」，而非「落后」。

## 4. 定位、用户与差异化（P4）

### 4.1 定位

用量化让人生**更美好、有的放矢**；在人生**关键节点**给出 **2～3 条路径 + trade-off**（Pareto 较优解，非唯一答案）。

### 4.2 目标用户（MVP）

- 25–40 岁，面临或刚经历**职业岔口**（Offer / 换工作）的知识工作者。
- 已有基本财务/时间概念，需要**结构化对比**而非鸡汤。
- 接受「粗算 + 假设清单」，不期待替代专业顾问。

### 4.3 差异化

| 维度 | 典型效率 App | Gauge |
|------|----------------|-------|
| 成功定义 |  streak、完成率 | 与自填主线的对齐度 |
| 大决策 | 清单 / 文章 | 规则引擎 + 多 Path 并列 |
| 量化边界 | 全量 KPI | 可关闭指标 + 叙述/底线必填 |
| 社交 | 排行、对比 | **无**排行 |

### 4.4 成功指标（MVP 可观测）

| 指标 | 定义 | MVP 目标（内测） |
|------|------|------------------|
| 完成 Onboarding | 价值观 + 主线 + A/B | ≥ 70% 安装用户 |
| 7 日签到留存 | 至少 3 次 check-in | ≥ 40% |
| Offer 向导完成率 | 四步走完并看到 PathCard | ≥ 60% 进入决策 Tab 的用户 |
| 复盘触达 | 复盘日打开 App 或导出 | 定性跟踪 |
| 负面 | 无「人生总分」相关反馈 | 0 次上线 |

## 5. 「关键节点最优解」定义（P5）

在用户当前 **State + 价值观权重 + 约束** 下，输出 **2～3 条 Pareto 方案**。每条包含：

- 分项：财务 / 时间 / 成长 / 稳定等（条形或标签，**非**加权总分排名）
- **可逆性**（高/中/低）
- **假设清单**（IF-THEN）
- **建议复盘日**（如决策后 +30 天）

**禁止**：人生总分、全球排名、单一 Winner 文案（可有「综合参考分」但须并列展示且带免责声明）。

**LLM（Out of MVP）**：只解释与追问；**数值由** `src/engine/job-offer.ts` **规则引擎计算**。

---

## 6. MVP 范围（P6）

### 6.1 In Scope

| 模块 | 能力 |
|------|------|
| **Onboarding** | 价值观 3 滑条（成长 / 稳定 / 风险）+ 1 条人生主线 + 锚点 A + 当前站 B |
| **今日** | 30 秒签到（精力 / 主线投入 / 情绪）+ 对齐度 + 7 日趋势 |
| **轨迹** | 阶段增删改 + 叙述 |
| **决策** | 仅「换工作 / Offer」四步向导 → 路径对比 + 假设 + 复盘日 |
| **设置** | 编辑主线、价值观、导出 JSON、产品原则 |

### 6.2 Out of Scope（MVP 不做）

- 账号同步、云端后端
- LLM 对话
- HealthKit / 地图
- 多决策节点类型（除 Offer 外）
- **人生总分**、排行榜 API
- Redux、人生排行榜类后端

## 7. 首发节点：Offer / 换工作（P7）

### 7.1 用户故事

作为正在考虑 Offer 的用户，我希望输入现状与 Offer 条件，看到**接受 / 留任 / 条件性谈判**等路径的粗算代价与假设，以便在复盘日验证选择。

### 7.2 输入字段

| 字段 | 必填 | 说明 |
|------|------|------|
| 当前年薪 | 是 | 税前，本地货币 |
| Offer 年薪 | 是 | 税前 |
| 单程通勤（分钟） | 是 | 相对现职变化可隐含在两条通勤字段或增量字段 |
| 每周加班（小时） | 是 | 现职 vs Offer 或增量 |
| 成长评分 1–10 | 是 | 主观 |
| 风险 / 稳定权重 | 是 | 来自 profile 或可覆盖 |
| 最不想失去的 3 样 | **是** | 文本，底线 |
| 可选叙述 | 否 | 不可量化上下文 |

### 7.3 输出

- 路径：**接受 / 留任 / 条件性谈判**（2～3 条 Pareto 呈现）
- 粗算：**税后年增**（简化税率模型，文档化假设）、**时间成本**（通勤 + 加班）
- 分项条：财务 / 时间 / 成长 / 稳定
- **综合参考分**（非唯一 Winner，并列 PathCard）
- 假设清单 + **复盘日**（默认 +30 天）

### 7.4 计算与质量

- 实现：`src/engine/job-offer.ts` 纯函数 + **zod** 校验
- 单元测试覆盖：边界值、缺失字段、三路径均非空
- 结果页顶部：**免责声明**（非职业 / 财务 / 法律建议）

## 8. 信息架构（P12）

### 8.1 Tab

| Tab | 核心内容 |
|-----|----------|
| 今日 | AlignmentRing + 签到 + Sparkline 7 日 |
| 轨迹 | 垂直 TimelineNode，A 锚点 + stages |
| 决策 | Offer 向导入口 + 历史决策列表 |
| 设置 | 主线 / 价值观 / 导出 JSON / 产品原则 |

### 8.2 Onboarding（三步）

1. 价值观（三滑条）  
2. 人生主线（一条陈述）  
3. 锚点 A + 当前站 B → 进入主 Tab  

---

## 9. 非功能需求

- **隐私**：MVP 数据本地存储（SQLite / Web AsyncStorage），导出 JSON 由用户自控。
- **可访问性**：滑条与环图需有文本读数；免责声明可读。
- **Web 验证**：`CI=1 npx expo start --web --port 8081`，页面标题 **「量化人生」**。
- **品牌**：产品名 **Gauge · 量化人生**；独立 EAS project，不与 cloudWardrobe 共用。
